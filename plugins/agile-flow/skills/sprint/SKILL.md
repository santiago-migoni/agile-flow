# Sprint

Read [the workflow map](../../AGENTS.md) and [the iterative lifecycle contract](../../references/iterative-lifecycle.md). Before writing, read [document operations](../../references/document-operations.md), [session protocol](../../references/session-protocol.md), and [authorization](../../references/authorization.md). Reuse sourced decisions and existing authorization. Resolve the product root; never edit the installed plugin cache.

Use the product engineer role. Reuse the release commitment, BL needs and pertinent design. Use plan-iteration and update-story for typed US/NFR/BUG/TCH/SPK work with criteria and individual DoD. Include goal, exclusions, tasks, verification and review_access describing how the owner will use the result and any environment lifetime. Estimates require a useful basis. An exploratory draft can retain uncertainty; resolve material selected-work questions before commitment. Use commit-sprint with the actual agreement source; this freezes scope, selected story definitions and tasks, but grants no implementation permission. Continue implement only under existing applicable execution authorization. Track task progress separately with track-task. Close through conclude-sprint after actual review and retrospective; unfinished work stays linked to BL records and is not automatically scheduled.
