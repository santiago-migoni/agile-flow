# Release

Read [the workflow map](../../AGENTS.md) and [the iterative lifecycle contract](../../references/iterative-lifecycle.md). Before writing, read [document operations](../../references/document-operations.md), [session protocol](../../references/session-protocol.md), and [authorization](../../references/authorization.md). Reuse sourced decisions and existing authorization. Resolve the product root; never edit the installed plugin cache.

Use the product manager role with engineering input. Delimit objective, bounded BL contributions, exclusions, exit conditions and optional MVP. Use update-release for drafts and commit-release only with the actual scope agreement source; no execution permission follows. Propose numbering if needed, preserving an unnumbered outline until resolved. For committed scope changes, use revise-release with impact and source; preserve active sprint commitments. Assess results with assess-release using actual outcomes and review sources. Completed scope does not mean published software. Continue sprint planning only within its mandate. Return product learning to strategy and backlog.
