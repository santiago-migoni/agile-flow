# Plan

Read [the workflow map](../../AGENTS.md), [collaboration protocol](../../references/collaboration-protocol.md), and [document ownership](../../references/document-ownership.md). Before record writes, read [session protocol](../../references/session-protocol.md), [document operations](../../references/document-operations.md), and [authorization](../../references/authorization.md). Preserve existing user decisions, authorization and authored notes. Use scoped Git operations only under the existing Git agreement; installation, publication and live migration remain separate actions.

Read [the product engineer role](../../references/roles/product-engineer.md) and [readiness and quality](../../references/readiness-and-quality.md). Confirm that the current mandate includes organizing a delivery; a product or architecture definition alone does not.

Reuse the release outcome, BL needs and relevant product-design/architecture decisions. Resolve necessary choices; keep future concerns deferred. For an explicitly requested exploratory plan, label assumptions and pending scope instead of promoting proposals into agreements. Create/refine the release and iteration only for this delivery, then typed US/NFR/BUG/TCH/SPK stories with observable criteria and own DoD. Use plan-iteration to select stories and capture baselines, tasks and checks. Do not fabricate story points; omit estimates when no useful basis exists.

Reference design decisions rather than duplicating architecture in sprint-planning.md. Surface unresolved assumptions and their consequences. Planning creates no execution authority. If existing authorization also covers implementation and work is ready, continue with implement without ceremonial reapproval; otherwise present the plan for the user's intended evaluation.

Use a delimited release and the selected work to assess readiness. Do not demand every future command or implementation detail before drafting a delivery plan. Retain explicit assumptions and resolve material viability questions before dependent commitments or execution. A mandate to delimit release scope alone belongs to define and does not create an iteration.
