# Implement

Read [the workflow map](../../AGENTS.md), [collaboration protocol](../../references/collaboration-protocol.md), and [document ownership](../../references/document-ownership.md). Before record writes, read [session protocol](../../references/session-protocol.md), [document operations](../../references/document-operations.md), and [authorization](../../references/authorization.md). Preserve existing user decisions, authorization and authored notes. Use scoped Git operations only under the existing Git agreement; installation, publication and live migration remain separate actions.

Read [the product engineer role](../../references/roles/product-engineer.md), [readiness and quality](../../references/readiness-and-quality.md), [record contracts](../../references/record-contracts.md), and [review and learning](../../references/review-and-learning.md).

Inspect the actual checkout, selected stories, baselines, current increment and authorization. Reuse permission that covers the scope; do not require a special phrase. Use prepare/start for sufficiently defined, authorized work and keep at most one active development increment. Resolve routine technical details; pause only work dependent on a necessary unresolved product or material design decision.

Implement against the journeys, criteria and DoD, preserving unrelated changes. Keep product-design.md and architecture.md consistent with actual decisions. Before reusing evidence, inspect fingerprints and effective_verification. Record mark-delivery-change before fresh verification for behavior or dependency changes. For non-behavioral covered-file changes, document impact on rerun evidence and obtain actual acceptance of the current result. Record checks with delivery scope, result, limitations and observable fingerprints.

Use prepare-correction on the same increment for requested changes or observed defects within its scope. If authorization was replaced, record the sourced replacement and rebind-authorization. Do not silently begin a different backlog item. Present the usable result, verification and remaining limits through review; passing tests never establish user acceptance.

Read [iterative lifecycle](../../references/iterative-lifecycle.md). Execute the committed sprint; classify discoveries before acting on them. Record task progress with track-task, preserve the agreed task plan, and deliver the promised owner access method. Opportunities return to backlog without automatic scheduling. Material scope changes use sourced interruption/replanning, never a silent baseline refresh.
