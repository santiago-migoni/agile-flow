# US-0001 — Book an available appointment

**Type:** US · **Status:** Draft proposal
**Order:** 1, proposed · **Estimate:** Not assigned; no repository assessment performed
**Target release:** v0.1.0 · **Iteration:** [ITER-001](../release/v0.1.0/iterations/ITER-001/sprint_planning.md), draft selection

## Need and value

Customers need to select a time and know whether it was booked, reducing message-based coordination.

## Scope

Include a single professional, prepared 30-minute slots, synthetic customer data and an explicit business time zone. Exclude availability administration, payments, cancellation and reminders.

## Type-specific detail

As a customer, I want to choose an available appointment and receive clear confirmation, so that I can arrange a visit without exchanging messages about availability.

## Acceptance criteria

| ID | Condition | Observable result |
| --- | --- | --- |
| AC-01 | Available slots exist. | Selectable dates/times identify the business time zone. |
| AC-02 | A selected slot is available on submission. | Exactly one booking persists; confirmation shows professional, time and reference. |
| AC-03 | Two requests compete for one slot. | Only one succeeds; the other explains the conflict and offers another selection. |
| AC-04 | The same submission is retried. | No duplicate booking is created and its actual result remains retrievable. |
| AC-05 | Availability is empty or the result is uncertain. | The interface explains the observed state without falsely confirming success. |
