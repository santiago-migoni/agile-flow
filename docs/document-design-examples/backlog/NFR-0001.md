# NFR-0001 — Complete booking using a keyboard

**Type:** NFR · **Status:** Draft proposal
**Order:** 2, proposed · **Estimate:** Not assigned; no repository assessment performed
**Target release:** v0.1.0 · **Iteration:** [ITER-001](../release/v0.1.0/iterations/ITER-001/sprint_planning.md), draft selection

## Need and value

Customers who do not use a pointer must be able to complete the booking journey and understand the result.

## Scope

Apply to the customer journey in US-0001. This example does not assert complete accessibility conformance.

## Type-specific detail

Quality attribute: keyboard operability and understandable feedback. Verify navigation, activation, focus and programmatically exposed status using the actual delivered UI.

## Acceptance criteria

| ID | Condition | Observable result |
| --- | --- | --- |
| AC-01 | Navigate without a pointer. | Controls are reachable in logical order with visible focus. |
| AC-02 | Select and submit using standard keyboard interactions. | The booking journey can be completed. |
| AC-03 | Success, validation or conflict occurs. | Feedback is programmatically exposed and focus is not trapped. |

## Definition of Done

| ID | Completion requirement | Required evidence |
| --- | --- | --- |
| DOD-01 | Exercise the implemented journey. | Recorded browser/environment and keyboard procedure, not only code inspection. |
| DOD-02 | Check labels, focus and status behavior. | Observed results with assistive-technology limits explicitly stated. |
| DOD-03 | Record and resolve deficiencies required by the agreed scope. | Linked corrections and rerun evidence; no unverified compliance claim. |

These item-specific conditions are proposals. No requirement is verified, no work is done and no user acceptance exists in this fictional example.

## Dependencies and open questions

Depends on a testable US-0001 UI. This item owns the quality details referenced by the story; it is not a second copy of the booking functionality.
