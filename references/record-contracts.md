# Record contracts

`.agile-flow/state.json` is the sole canonical plugin record. Generated Markdown under `.agile-flow/views/` is a projection, not an editable authority. The program writes backups, uses a same-directory temporary file followed by atomic replacement, locks cooperating writers, and validates schema, references, operation IDs, revisions, fingerprints, and the single-active-increment rule.

Supported mutations are `initialize`, `update-project`, `update-backlog`, `complete-backlog`, `record-decision`, `prepare`, `start`, `mark-implemented`, `prepare-correction`, `record-evidence`, `record-review`, `record-blocker`, `resolve-blocker`, `record-improvement`, `follow-up-improvement`, `mark-delivery-change`, `pause`, `resume`, `close`, and `reopen`. `mark-delivery-change` is the explicit internal operation that creates a later delivery revision and preserves prior evidence. `prepare-correction` reopens the same increment after requested changes.

Manual state or generated-view edits stop mutation until reconciled. `reconcile-manual` requires the raw state hash, reviewer, and reason, preserves the edited file, then seals a structurally valid reviewed state. It cannot authenticate that review. Explicit `recover` verifies backup integrity under the lock and preserves each damaged snapshot; it never silently restores a backup. `inspect` compares recorded file hashes and reports stale evidence without mutating canonical state.
